# Postern

> Drive a live Pharo image over HTTP from a coding agent or shell.

[![License](https://img.shields.io/github/license/punt-labs/postern)](LICENSE)
[![CI](https://img.shields.io/github/actions/workflow/status/punt-labs/postern/test.yml?label=CI)](https://github.com/punt-labs/postern/actions/workflows/test.yml)
[![Pharo 12](https://img.shields.io/badge/Pharo-12-%23aac9ff.svg)](https://pharo.org/download)

Postern runs an HTTP server inside a Pharo image, the saved state of a
running Smalltalk system. Clients send Smalltalk code to `/repl` and read
documentation from `/help`, so a shell script, CI job, or coding agent can
compile, test, inspect, and commit code without the Pharo GUI. It is meant
for local development and CI on a machine you control.

**Platforms:** macOS, Linux, Windows (Windows on ARM64: headless only)

## Quick Start

```bash
git clone https://github.com/punt-labs/postern.git
```

```bash
cd postern
```

```bash
make setup
```

```bash
make start
```

`make setup` downloads the Pharo 12 VM and image for your machine and
loads the Postern packages. `make start` opens the Pharo window and starts
the server on `http://localhost:8422`. To run without a window, use
`make start-headless` instead.

<details>
<summary>Verify the server</summary>

```bash
curl -s http://localhost:8422/health
```

The response is `ok`.

</details>

<details>
<summary>Headless Linux, Windows on ARM64, and port conflicts</summary>

- On Linux without `DISPLAY` or `WAYLAND_DISPLAY`, `make start` stops with
  an error. Use `make start-headless`.
- On Windows on ARM64, `make setup` installs the Windows `x86_64` Stack VM,
  which runs under emulation and has no GUI. Use `make start-headless`.
- If port `8422` is taken, set another port on each command, for example
  `make PORT=8432 start-headless`.
- If Pharo cannot write to its usual configuration directories (for
  example inside a Codex or Claude Code sandbox), Postern uses
  `.tmp/pharo-home` in the repository instead.

</details>

Before you expose Postern beyond your machine or give an agent access,
read [Security](#security).

## Features

- **HTTP REPL** --- evaluate Smalltalk in the running image with `POST /repl`.
- **Live help** --- `/help` is generated by the running image and describes the loaded packages and the workflow.
- **GUI or headless** --- `make start` opens the Pharo window; `make start-headless` runs without one.
- **Dashboard** --- `PosternDashboard` shows each request's method, path, status, duration, and a body snippet.
- **Iceberg sync** --- Iceberg is Pharo's Git client. Postern adds a command that clears the false "dirty" state Iceberg shows after you commit or merge with command-line `git`.
- **Optional token auth** --- local-only mode can run without a token; listening on all network interfaces always requires one.

## Commands

Run these from the repository root. Add `PORT=<n>` to any target to use a port other than 8422.

| Command | What it does |
|---------|--------------|
| `make setup` | Download Pharo and load the Postern packages into the image |
| `make start` | Start Pharo with its window and the server on port 8422 |
| `make start-headless` | Start Pharo without a window and the server on port 8422 |
| `make stop` | Stop Pharo without saving the image |
| `make status` | Check the server and count the loaded Postern classes |
| `make eval` | Send Smalltalk from standard input to `/repl` |
| `make transcript` | Print the Pharo Transcript (the image's log) |
| `make rebuild` | Stop Pharo, delete the image, and build a new one from `src/` |
| `make clean-image` | Delete the image, logs, setup state, and runtime home |
| `make clean` | Delete the downloaded Pharo directory |

## API

### HTTP Routes

| Route | Method | Description |
|-------|--------|-------------|
| `/repl` | `POST` | Evaluate Smalltalk from a `text/plain` body and return the `printString` of the result. |
| `/health` | `GET` | Return `ok`. No auth required. |
| `/help` | `GET` | Return the table of contents for the live help. No auth required. |
| `/help/{section}` | `GET` | Return one help section: `api`, `browse`, `pharo`, `dispatch`, `lint`, `git`, `testing`, `safety`, `makefile`, or `lessons`. No auth required. |

Send LF line endings. The server converts them to CR, which the Pharo
compiler expects. `/help` responses use LF.

### Binding and Authentication

`make start` and `make start-headless` call `PosternServer startOn:`,
which listens on localhost without auth. To choose a different mode,
evaluate one of these in the image:

| Method | Listens on | Auth |
|--------|------------|------|
| `PosternServer startOn: 8422` | localhost | none |
| `PosternServer startOn: 8422 withAuth: true` | localhost | required |
| `PosternServer startPublicOn: 8422` | all interfaces | required |

There is no mode that listens on all interfaces without auth. When auth
is on, the server writes a random token to `.tmp/eval-token`, and `/repl`
requires that token in an `X-Eval-Token` header:

```bash
curl -s -X POST http://localhost:8422/repl -H "Content-Type: text/plain" -H "X-Eval-Token: $(cat .tmp/eval-token)" -d "3 + 4"
```

### Dashboard

Open it from the World menu with **Postern > Dashboard**, or evaluate:

```smalltalk
PosternDashboard open.
```

The dashboard lists each request: method, path, status code, duration,
and a body snippet. Type in the filter field to narrow the list; it has
keyboard focus when the window opens. Each `PosternDashboard open`
opens a new window; if more than one server is running, it asks which
one to watch.

### Iceberg Sync

After you commit, pull, or merge with command-line `git`, Iceberg's
record of the current commit (its reference commit) can differ from the
repository's `HEAD`, and Iceberg shows the packages as changed when they
are not. To fix it, select the repository in the Iceberg repositories
browser and choose **Sync reference commit**, or evaluate this with
`repo` bound to the `IceRepository`:

```smalltalk
repo workingCopy referenceCommit: repo head commit.
```

## Setup

### Load into Another Image

Load the default group (`Postern-Core`, `Postern-Dashboard`,
`Postern-IcebergExtensions`):

```smalltalk
Metacello new
  baseline: 'Postern';
  repository: 'github://punt-labs/postern:main';
  load.
```

Load the default group and the tests:

```smalltalk
Metacello new
  baseline: 'Postern';
  repository: 'github://punt-labs/postern:main';
  load: 'all'.
```

### Agent Access

An agent should read the live help before it writes Smalltalk. Start with
the table of contents:

```bash
curl -s http://localhost:8422/help
```

Then read the sections the task needs, for example:

```bash
curl -s http://localhost:8422/help/api
```

| Section | What it documents |
|---------|-------------------|
| `/help/api` | Endpoints, auth, request and response format |
| `/help/browse` | Read-only lookups: classes, methods, senders, implementors, source |
| `/help/pharo` | Pharo 12 conventions: class definition syntax, method categories, JSON |
| `/help/dispatch` | How to hand a task to another agent: a request template, the test-first cycle, common mistakes |
| `/help/lint` | Code checks: `make lint` must report every class clean |
| `/help/git` | Committing with Iceberg, merging with command-line `git`, keeping packages safe |
| `/help/testing` | Running the tests for one package instead of the whole image |
| `/help/safety` | Calls that hang the image, rules for a disposable image, cleaning up leftover processes |
| `/help/makefile` | Image lifecycle: setup, start, stop, rebuild |
| `/help/lessons` | Past incidents and the checks added after them |

Agent tools often block `curl` to `localhost` until you allow it. In
Codex or Claude Code, use `/permissions`. For Codex, this repository
includes `.codex/config.toml` and `codex/rules/default.rules`, which allow
the common Postern requests once you trust the repository. See
[AGENTS.md](AGENTS.md) for the full agent checklist.

## Security

Postern accepts Smalltalk code over HTTP and runs it in the image. A
client that can call `/repl` can do anything Smalltalk code in that image
can do: change classes and methods, inspect objects, read and write
files, and run shell commands with the operating-system permissions of
the user running Pharo.

By default, `make start` and `make start-headless` listen on `localhost`
only and do **not** enable auth. When auth is on, the `X-Eval-Token` is a
shared secret for `/repl`; it is not a sandbox, permission system, or
read-only mode. `/help` and `/health` never require the token.

Do not expose Postern to untrusted networks or untrusted agents. Do not
run it where there are secrets or data you would not give to arbitrary
code running as your user account.

## Live Image Model

Pharo keeps code and data together in one set of live objects, the
image. Compiling a method installs it in the image at once. In one
session you can define a class, call its methods, run its tests, and
inspect the objects it creates, without restarting a process.

For an agent, each `/repl` request runs against the same image, so the
next request can call a method compiled by the previous one and act on
the actual result. Iceberg also runs inside the image, so commits happen
in the same session.

## Agent Workflow

An agent can complete an edit cycle over HTTP: read the help, define a
class, compile a method, run a test, and commit. Each request below is
one command.

Define a class:

```bash
curl -s -X POST http://localhost:8422/repl -H "Content-Type: text/plain" -d "(Object << #Counter slots: { #count }; package: 'MyPackage') install"
```

Compile a method:

```bash
curl -s -X POST http://localhost:8422/repl -H "Content-Type: text/plain" -d "Counter compile: 'increment count := (count ifNil: [ 0 ]) + 1. ^ count' classified: 'actions'"
```

Define a test class:

```bash
curl -s -X POST http://localhost:8422/repl -H "Content-Type: text/plain" -d "(TestCase << #CounterTest package: 'MyPackage') install"
```

Compile a test:

```bash
curl -s -X POST http://localhost:8422/repl -H "Content-Type: text/plain" -d "CounterTest compile: 'testIncrement self assert: Counter new increment equals: 1' classified: 'tests'"
```

Run the test:

```bash
curl -s -X POST http://localhost:8422/repl -H "Content-Type: text/plain" -d "CounterTest buildSuite run"
```

The response is
`1 ran, 1 passed, 0 skipped, 0 expected failures, 0 failures, 0 errors, 0 passed unexpected`.

Commit. This step assumes `MyPackage` belongs to a Git repository that
Iceberg knows as `my-project`:

```bash
curl -s -X POST http://localhost:8422/repl -H "Content-Type: text/plain" -d "| repo | repo := IceRepository registry detect: [ :r | r name = 'my-project' ]. repo workingCopy refreshDirtyPackages. repo workingCopy commitWithMessage: 'feat(counter): add increment'"
```

## Packages

| Package | Contents | Metacello group |
|---------|----------|-----------------|
| `Postern-Core` | The HTTP server, `/repl`, `/help`, and auth | `default` |

## Trivia

A postern is a small secondary gate in a castle or city wall. Postern
gives tools a side entrance into a live Pharo image, so the GUI is not
the only way in.
